# M6 — Benchmark

**Goal.** Scored, reproducible, comparable. Two people on two machines get the same number
for the same model.

**Depends on.** M4. **Parallel with.** M5, M7.
**Size.** Medium.

---

## Deliverables

### 1. The scenario suite

Each scenario is a versioned file, seeded, with a stated purpose. Minimum set:

| scenario | tests |
|---|---|
| `steady` | baseline competence under stationary load |
| `contention` | many hosts, few good paths — the herding case |
| `diurnal` | slow predictable variation |
| `regime-shift` | traffic pattern changes mid-episode; overfitting |
| `churn` | aggressive re-signing; identity amnesia |
| `outage` | scheduled link failure and recovery |
| `cold-start` | most paths never observed |
| `defectors` | 10/25/40% greedy population (PAS v3 adversary classes) |
| `budget-squeeze` | probe budget cut to a fraction |
| `slow-model` | injected decision latency |

Scenarios are the portable artefact. They must run at every tier — check that against the
`linkd` REST surface now rather than discovering an impedance mismatch at M9.

### 2. Scoring

Per-scenario scores in the three metric families, then an aggregate with **published
weights**. Never a single opaque number: a model that trades stability for efficiency
should be visibly doing that.

Report the perfect-information upper bound and the capacity-proportional floor alongside
every score. A model that cannot beat capacity-proportional has not earned its complexity.

### 3. Reproducibility manifest

Every result file carries: scionarena version, scenario version and hash, seed, model
name/version/capabilities, hardware, wall-clock, and a trace hash. A result without a
manifest is not a result.

### 4. The G-experiments

G1–G6 from the architecture proposal live here — they are experiments, not conformance
checks. Encode E0–E8 as benchmark configurations so the architecture's own claims are
testable by anyone:

- **E5 is the central one**: the same model with and without demand conditioning, in closed
  loop, showing whether the oscillation collapses. Ship it as a named, runnable config.

### 5. Wrap ScionPathML's tasks

Their five open-loop tasks as a bench category, so a model gets an open-loop score and a
closed-loop score side by side. Their Task 4 rewards top-ranked-path accuracy; showing it
next to our R8 and the oscillation index in one table makes the gap concrete without
editorialising. Coordinate before publishing anything comparative.

---

## Acceptance criteria

- [ ] Two machines produce identical scores for the same model, scenario and seed
- [ ] A result file alone is enough to reproduce the run
- [ ] All ten scenarios run at `realistic` within a stated time budget
- [ ] E5 runs as a single command and produces the headline figure
- [ ] Baselines scored and published as the reference table
- [ ] Scenario schema validated against `linkd`'s REST surface (design check, not execution)

## Must not break

Determinism. Scenario portability across tiers.
