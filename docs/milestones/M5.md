# M5 — Conformance v2

**Goal.** Port R1–R10 onto the real substrate, rewrite R4 against the corrected domain,
and add the probes that test the AI's own operational behaviour.

**Depends on.** M4. **Parallel with.** M6, M7.
**Size.** Medium.

---

## Deliverables

### 1. Port R1–R10

Same behavioural discipline: change one thing, compare a model against itself. Now running
against the real substrate at `dev` scale by default and `realistic` on demand. R1, R2,
R3, R5, R6, R7, R8, R9, R10 port largely unchanged in intent; their implementations get
rewritten against the new tool-mediated exposure.

### 2. Rewrite R4 — identity churn resistance

**The old R4 tested the wrong thing.** It introduced new interfaces, which the corrected
domain model says does not happen at that rate.

New R4: run the same episode twice, once under `identity_policy: structural` and once
under `crypto_bound`. The interface sequences are identical in both. Only the exposed
identifier differs.

- A model keyed on path structure performs equivalently under both → **PASS**
- A model keyed on the exposed identifier collapses under `crypto_bound` while looking
  fine under `structural` → **FAIL**, with the per-refresh sawtooth as evidence

This is a better probe than the one it replaces, and it is the direct payoff of the
mentor's correction. Report the delta between policies as the score.

### 3. New probes: the AI's own behaviour

| id | requirement | probe |
|---|---|---|
| **A1** | respects a deadline | shrink the decision budget; does the model degrade gracefully or blow through it? |
| **A2** | probes economically | information gained per unit probe cost, versus a random-probing control |
| **A3** | manages its own memory | grow history to 10^6 events; does performance hold and does footprint stay bounded? |
| **A4** | survives context growth | performance versus history length, with distractor injection |
| **A5** | handles budget exhaustion | exhaust the probe budget mid-episode; does behaviour stay sane? |
| **A6** | tolerates a stale world | freeze telemetry; does the model detect it and widen? |

A1–A6 need `ToolUsingModel`. For a plain `PathModel` they report `NOT_APPLICABLE`, which
is the honest answer, not a free pass.

### 4. Verdict model extended

Existing verdicts stay. Add an **operational grade** orthogonal to conformance, because a
model can be structurally perfect and operationally unusable. Report both.

---

## Acceptance criteria

- [ ] R1–R10 run against the real substrate; matrix still discriminates
- [ ] R4 correctly separates a structure-keyed model from an identity-keyed one
- [ ] Each of A1–A6 has a reference model that fails it
- [ ] Conformance over `dev` completes in under 60 s
- [ ] A plain `PathModel` gets `NOT_APPLICABLE` on A1–A6, never a default pass
- [ ] Reference models updated: at least one now uses tools

## Must not break

The `DECLARED_ABSENT` / `FALSE_CLAIM` asymmetry. `test_probes_discriminate`.
