# M7 — RL environment

**Goal.** Anyone who wants to train a model for SCION uses this, and gets rich tool access
rather than a flattened feature vector.

**Depends on.** M4. **Parallel with.** M5, M6.
**Size.** Medium-large.

---

## Deliverables

### 1. `gym/env.py` — Gymnasium API

`reset` / `step` / `render` / `close`, passing `gymnasium.utils.env_checker`.

**Two action interfaces over the same substrate**, because the two audiences are different
and forcing either into the other's shape wastes the environment:

- **flat** — observation is a fixed-size array, action is a simplex over the top-K paths
  plus a probe budget scalar. For PPO/SAC and anything expecting classic RL.
- **tool-calling** — observation is the raw event delta, action is a tool call. For LLM
  agents and anything that should decide *what to look at*. This is the interesting one.

The flat interface necessarily does some flattening, which brushes against invariant 1.
That is acceptable **only** in `gym/flat`, must be documented as a deliberate exception,
and the flattening code must live in `gym/`, never in `exposure/`.

### 2. `gym/spaces.py`

Variable path counts, variable scope counts. Padding and masking for the flat interface;
JSON schemas for the tool interface.

### 3. Reward

Composable terms with published weights: utility, stability penalty, probe cost, latency
penalty, fairness. Ship named presets (`efficiency`, `stability`, `balanced`) so results
are comparable, and make custom rewards easy so researchers are not fighting us.

**Document the reward-hacking surface.** An agent that learns to never publish an advisory
avoids every stability penalty. Say so in the docstring and add it as a detector.

### 4. Vectorisation and curricula

`SyncVectorEnv` and `AsyncVectorEnv`. Throughput target below. Curriculum support:
scale up from `smoke` to `realistic`, host count from 10 to 10k, scenario difficulty
ordered.

### 5. A trained baseline

One PPO agent trained to beat capacity-proportional on `steady` and `contention`. Its
purpose is to prove the environment is learnable, not to be a good model. Ship weights and
the training script; keep it deliberately unambitious.

---

## Acceptance criteria

- [ ] Passes `gymnasium.utils.env_checker` on both action interfaces
- [ ] Vectorised throughput: ≥ 1,000 steps/s at `dev`, ≥ 100 steps/s at `realistic`
- [ ] PPO baseline beats capacity-proportional on `steady` and `contention`
- [ ] An LLM agent completes an episode through the tool interface
- [ ] Curriculum runs `smoke` → `realistic` without code change
- [ ] Reward presets documented with weights; reward-hacking surface listed
- [ ] No flattening code outside `gym/`

## Must not break

Invariant 1 outside `gym/flat`. Determinism given a seed.

## Notes

The reason to support both interfaces is that the project's actual bet is the tool-calling
one — that a model which chooses what to measure beats one handed a fixed view. The flat
interface exists so that bet can be *tested* against a conventional baseline rather than
asserted.
