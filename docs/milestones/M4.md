# M4 — Instrumentation and pathology detectors

**Goal.** Everything that happens is recorded in a machine-readable trace, and the
pathologies we care about are detected automatically rather than eyeballed.

**Depends on.** M3. **Blocks.** M5, M6, M7, M8.
**Size.** Medium.

---

## Deliverables

### 1. `instrument/events.py` — the trace

Append-only, typed, streamable event log covering: substrate state transitions, every tool
call with cost and latency, every advisory, every host outcome, every budget change.
Written in a columnar format (parquet or arrow) so a long run stays analysable.

The trace is written to and never read by the model. It is the artefact everything else is
computed from, and it must be sufficient to reconstruct a run without re-executing it.

### 2. `instrument/metrics.py` — the registry

Pluggable metrics in three families. Registering a metric must not require touching the
runner.

**Task** — pinball loss, CRPS, calibration coverage, utility against the perfect-
information bound, efficiency against the capacity-proportional floor.

**Operational** — decision wall-clock distribution, tool calls per decision, information
gained per unit cost, budget utilisation, behaviour at exhaustion, memory footprint.

**Pathology** — see below.

### 3. `instrument/detectors.py` — the pathologies

Each detector ships with a synthetic positive and a synthetic negative. A detector that
has never fired in a test is not trusted.

| detector | what it catches |
|---|---|
| oscillation | fast-band spectral peak in link utilisation |
| herding | modal-path share versus host count |
| identity amnesia | per-path state discontinuity across a re-signing event |
| context rot | performance degradation as history length grows |
| staleness misuse | confidence that does not decay with information age |
| budget abuse | probing far past the point of information gain |
| overfit | train/eval gap across disjoint topology partitions |

**Identity amnesia** is new and specific to the corrected domain model. Detect it by
correlating a drop in prediction quality with re-signing events. A model keyed on
`segment_id` shows a sawtooth locked to the beacon interval; that signature is
unmistakable once you look for it, and invisible if you do not.

### 4. `instrument/report.py`

Terminal, JSON, markdown, and an HTML trace viewer. The viewer is for post-hoc inspection
only and must never be in the decision loop.

---

## Acceptance criteria

- [ ] A `realistic` run produces a trace that reconstructs all metrics without re-execution
- [ ] Trace overhead under 10% of runtime
- [ ] Every detector fires on its synthetic positive and stays silent on its negative
- [ ] Identity-amnesia detector fires on a deliberately `segment_id`-keyed model under
      `crypto_bound`, and does not fire on the same model under `structural`
- [ ] A new metric can be registered without editing the runner
- [ ] Trace format documented well enough for an outside analysis script

## Must not break

Invariant 1 — the trace is write-only from the model's side. No detector output leaks back
into what the model can observe.
