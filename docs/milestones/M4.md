# M4 — Instrumentation and pathology detectors

**Goal.** Everything that happens is recorded in a machine-readable trace, and the
pathologies we care about are detected automatically rather than eyeballed.

**Depends on.** M3. **Blocks.** M5, M6, M7, M8.
**Size.** Medium.

---

## Deliverables

### 1. `instrument/events.py` — the trace

Append-only, typed, streamable event log covering: substrate state transitions, every tool
call with cost and latency, every advisory, every host outcome, every budget change.
Written in a columnar format (parquet or arrow) so a long run stays analysable.

The trace is written to and never read by the model. It is the artefact everything else is
computed from, and it must be sufficient to reconstruct a run without re-executing it.

### 2. `instrument/metrics.py` — the registry

Pluggable metrics in three families. Registering a metric must not require touching the
runner.

**Task** — pinball loss, CRPS, calibration coverage, utility against the perfect-
information bound, efficiency against the capacity-proportional floor.

**Operational** — decision wall-clock distribution, tool calls per decision, information
gained per unit cost, budget utilisation, behaviour at exhaustion, memory footprint.

**Pathology** — see below.

### 3. `instrument/detectors.py` — the pathologies

Each detector ships with a synthetic positive and a synthetic negative. A detector that
has never fired in a test is not trusted.

| detector | what it catches |
|---|---|
| oscillation | fast-band spectral peak in link utilisation |
| herding | modal-path share versus host count |
| identity amnesia | per-path state discontinuity across a re-signing event |
| context rot | performance degradation as history length grows |
| staleness misuse | confidence that does not decay with information age |
| budget abuse | probing far past the point of information gain |
| overfit | train/eval gap across disjoint topology partitions |

**Identity amnesia** is new and specific to the corrected domain model. Detect it by
correlating a drop in prediction quality with re-signing events. A model keyed on
`segment_id` shows a sawtooth locked to the beacon interval; that signature is
unmistakable once you look for it, and invisible if you do not.

### 4. `instrument/report.py`

Terminal, JSON, markdown, and an HTML trace viewer. The viewer is for post-hoc inspection
only and must never be in the decision loop.

---

## Acceptance criteria

- [ ] A `realistic` run produces a trace that reconstructs all metrics without re-execution
- [ ] Trace overhead under 10% of runtime
- [ ] Every detector fires on its synthetic positive and stays silent on its negative
- [ ] Identity-amnesia detector fires on a deliberately `segment_id`-keyed model under
      `crypto_bound`, and does not fire on the same model under `structural`
- [ ] A new metric can be registered without editing the runner
- [ ] Trace format documented well enough for an outside analysis script

## Must not break

Invariant 1 — the trace is write-only from the model's side. No detector output leaks back
into what the model can observe.

## Progress

### 0. `instrument/sampler.py` — the x axis, before anything is measured on it

Not in the deliverable list above; it is M3's known limitation, which §6 of `HANDOFF.md`
says M4 starts by fixing, and every criterion in this milestone is measured on the grid it
produces. Done: [ADR 0011](../adr/0011-sampling-off-the-worlds-clock.md). Evidence in
`docs/evidence/m4-sampling/` (three tables and the script that makes them) and
`docs/evidence/m4-smoke/`.

- [x] Samples come off a `Substrate` tap on multiples of absolute simulated time, not once
      per decision round
- [x] The configuration M3 could not keep a grid on — 24 scopes, held 30 s cadence, 12/12
      rounds overrunning — gives 29 samples over 870 s of world time, every gap 30 s,
      jitter 0.0
- [x] A grid point crossed without a tick is counted in `Series.skipped`, never
      interpolated, and `uniform()` then reports false
- [x] `sample_s` defaults to the cadence, so M3's axis and every threshold written against
      it are reproduced exactly; a 10x change in sample rate moves the headline amplitude
      by 5%
- [x] Sampling slower than the cadence is refused as sub-Nyquist for the fastest thing the
      model can do; measured, 4x undersampling loses half the amplitude and raises dominance
      for both models
- [x] The fast band is defined in decision rounds (`FAST_BAND_MAX_ROUNDS`) and converted per
      run, so an off-cadence series is measured over the same span of world
- [x] `adaptive_cadence` off by default, kept as a controlled comparison
- [x] M3's scope sweep re-measured on a held cadence, next to the original numbers rather
      than over them — amplitude reproduces, peak dominance does not and moves the opposite
      way, which is recorded in M3.md and noted on ADR 0010

## Corrections carried in during M4

The mentor's re-review of the harness at `7f83fe4` against Master Spec v1.2 found four
substrate defects and answered two open questions from the `scionproto` source tree. All
six are closed. None of the four failed anything in a 400-test suite, which is the property
that made them worth writing up rather than merely fixing.

- [x] **C1 — the AS policy filter leaked.** `_on_policy_filter` hid the segments that
      existed when the event fired; composition is lazy, so every core segment discovered
      afterwards escaped. 335 paths over 60 sampled pairs at `dev` still traversed a
      filtered AS. Filtering is now a standing `FilterPolicy` tested at registration
      ([ADR 0012](../adr/0012-filtering-is-a-rule-and-probe-limits-belong-to-the-scenario.md)).
- [x] **C2 — the bandwidth probe left load behind.** A host grid tick inside the probe's two
      seconds rebuilt demand and dropped its contribution; the matching subtraction then
      landed on a baseline that never carried it. Exactly `-50 Mbps` on an idle interface,
      and an equal understatement on a busy one. Probe load is now held by the substrate
      and included when demand is rebuilt.
- [x] **C3 — the beacon stream dropped 75% of re-signings.** `_resign_all` assigned rather
      than extended the pending list. Replaced by `drain_resigned()`, so the reader owns
      the clear.
- [x] **B1 — the beacon interval was 60x too slow.** 300 s against upstream's 5 s. Expiry is
      now quantised to `EXPIRY_QUANTUM_S = 337.5`, one of 256 discrete steps.
- [x] **Q1 resolved — the fingerprint is structural.** `identity_policy` defaults to
      `structural`. R4's re-aim is M5's work and is specified in `OPEN_QUESTIONS.md`.
- [x] **Q6 resolved — there is no SCMP rate limiter.** The three invented constants move to
      `Scenario.probe_limits`, so a run states its regime and M6 sweeps it.

**What B1 cost, and what it did not.** Correcting the cadence made re-signing the
substrate's dominant per-step cost: `substrate_step_s` went from 0.20 ms to 9.9 ms at the
realistic tier, a 54x rise tracking the 60x change in frequency. Two causes, both profiled
rather than guessed: two scalar numpy RNG draws per segment per round (batched: 9.9 → 4.3 ms)
and `dataclasses.replace` per segment, 542k calls doing 2.7M reflective getattrs
(constructed directly: 4.3 → **2.09 ms**). `benchmarks/baseline.json` is re-recorded on that
basis; only `substrate_step_s` moved and everything else sits within ±3%, which is the
signature of a workload change rather than a regression.

**What it did not cost: the M3 headline result is unchanged.** `docs/evidence/m4-smoke.log`
re-recorded at the corrected cadence reproduces the previous numbers exactly — 3.300 vs
0.546 link amplitude, 6.05x. That is expected and worth stating: the demo runs under
`structural`, where re-signing does not move `path_id`, so the oscillation result never
depended on the beacon interval. B1 moves the *identity* result and nothing else.

**And it moves that one by 22.5x.** `docs/evidence/b1-identity-churn.log`, reproducible with
`docs/evidence/b1_identity_churn.py`: over 6,000 s under `crypto_bound`, one unchanging set
of six paths presents **6,674 distinct identifiers at the corrected cadence against 296 at
the assumed one**, from 47,096 re-signings against 1,146. The structural ids are identical
in both, which is the whole point — the interface sequences never moved, so this measures
what a model keyed on the wrong identifier discards, not what SCION does to a correct one.

**Still standing.** `Segment` is a frozen dataclass rebuilt per re-signing, which is
CLAUDE.md's "array-backed, no Python object per thing in the hot loop" rule bending. Moving
segment material into arrays would take the step further down; it is a refactor, not a
bugfix, and is not attempted here.
