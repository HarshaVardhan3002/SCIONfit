# M3 — The closed loop

**Goal.** Advice changes traffic, traffic changes link state, link state changes the next
observations. Demonstrate the oscillation result at realistic scale rather than in a toy.

**Depends on.** M1, M2. **Blocks.** M5–M9.
**Size.** Medium.

---

## Deliverables

### 1. `core/hosts.py` — the host population

N hosts per (src, dst, SLA) scope. Each host independently samples a path set from the
published advisory, generates traffic, and reports what it experienced. Configurable:
population size, SLA mix, arrival/departure, and a **defector fraction** that ignores the
advisory and plays greedy (this is the PAS v3 adversary taxonomy; wire the hook now, the
classes come in M6).

Sampling is independent by design. The realised split concentrates on the intended split
at `O(1/√N)` with no coordination, and that property is what the whole stochastic-advisory
argument rests on. Test it directly.

### 2. Loop closure

`advisory → host sampling → per-link offered load → link state → observations → advisory`.

Advisory application is **delayed by the model's decision latency**. A decision taken 800
simulated ms after the state it was computed from is applied against the state that exists
800 ms later. Invariant 3, made concrete.

### 3. Multi-scope

Many (src, dst) pairs active simultaneously, sharing links. Cross-scope coupling through
shared bottlenecks is where the interesting behaviour lives and where a single-scope
harness would mislead.

### 4. `instrument/detectors.py` (first cut) — oscillation

Oscillation index: spectral peak dominance restricted to the fast band, excluding slow
environmental drift. The existing implementation in `conformance` is correct in principle;
port it, and note in the code why the fast-band restriction exists (environment tracking is
not oscillation, and an earlier version conflated them).

---

## Acceptance criteria

- [ ] Greedy reference model oscillates at `realistic` scale, oscillation index > 0.5
- [ ] Stochastic reference does not, index < 0.15, same scenario and seed
- [ ] Realised split matches intended within the `1/√N` envelope at N = 100, 1k, 10k
- [ ] Decision latency demonstrably shifts application time; a slow model is measurably worse
- [ ] Multi-scope run with ≥ 100 concurrent scopes over `realistic` completes in budget
- [ ] Defector fraction hook exists and a 20% always-greedy population changes the outcome
- [ ] Whole loop deterministic from seed

## Must not break

Determinism. Invariant 3.

## Notes

**This milestone contains the project's headline result.** The figure is link utilisation
over time, ranked-advice versus sampled-advice, at realistic scale. If it does not
reproduce here, that is the most important negative finding the project can produce and it
must be reported, not tuned away.

### The headline, at the smoke tier, 240 rounds, seed 7

Both models on one scenario, one seed, one set of scopes; nothing differs but the model.
`docs/evidence/m3-scope-sweep.log`, reproducible with `scionarena demo`:

| scopes | cadence | amplitude, greedy | amplitude, stochastic | ratio | cost ratio | dominance, greedy | dominance, stochastic |
|---|---|---|---|---|---|---|---|
| 4 | 30 s | 3.33 | 0.32 | 10.5x | 2.06x | 0.330 | 0.076 |
| 8 | 30 s | 3.25 | 0.54 | 6.0x | 2.89x | 0.507 | 0.148 |
| 16 | 71 s | 3.00 | 0.30 | 10.2x | 1.53x | 0.712 | 0.157 |
| 24 | 121 s | 4.46 | 0.24 | 18.7x | 1.32x | 0.848 | 0.279 |

**The oscillation is real and large at every scale.** The greedy model throws its whole
population from one path to another and back; the amplitude ratio never drops below six.

**The proposal's index is not scale-stable, which is why it is no longer the criterion.**
Peak dominance climbs from 0.33 to 0.85 across a 6x change in the number of scopes,
straight through the 0.5 threshold, so that threshold means different things at different
sizes. Series length does the same: at 4 scopes, 100 rounds gives 0.375 against 0.249 and
240 rounds gives 0.330 against 0.076. The criterion is therefore restated as a ratio
between two models on one scenario, with amplitude as the headline; both numbers stay on
the report card.

**One claim was withdrawn.** ADR 0010 first reported that dominance ranked the two models
*backwards*. That measurement was taken before the cadence bug below was found, on a
series that was not uniformly sampled. It does not reproduce, and the ADR says so.

### Two bugs worth carrying forward

1. **The decision cadence did not fit the round, and nothing looked wrong.** Probes are
   charged per scope, so a round's cost grows with the number of scopes: at 40 scopes all
   240 rounds overran a 30 s cadence and the world advanced by whatever the turns happened
   to cost. The series was still the right length and the numbers were still plausible.
   Every detector here assumes uniform sampling and none of them can tell when that is
   untrue. `run_loop` now calibrates the cadence from a few unsampled rounds; the cadence
   it kept is on the report card.
2. **Ranking tracked interfaces by raw crossings picks the ones that cannot move.** An
   interface every path of a scope uses -- the access link out of the source -- carries
   the whole scope whatever the advice says, so a figure drawn on it shows every model as
   calm. Interfaces are ranked by contestedness, `p(1-p)`, and there is a test.

### Known limitation

Calibration takes the worst of three unsampled rounds and adds 30%, which is enough for
the greedy model but not always for the stochastic one: it lights up far more paths as it
runs, telemetry is charged per record, and the cost of a round therefore grows through
the episode. At 16 scopes the stochastic run still overran 120 of 240 rounds. The fix is
to sample on the world's own clock rather than once per decision round, decoupling the
sample grid from the model's spending; it is written up for M4 because it changes what a
series *is* and every detector test with it.
