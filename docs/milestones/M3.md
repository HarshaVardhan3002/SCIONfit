# M3 — The closed loop

**Goal.** Advice changes traffic, traffic changes link state, link state changes the next
observations. Demonstrate the oscillation result at realistic scale rather than in a toy.

**Depends on.** M1, M2. **Blocks.** M5–M9.
**Size.** Medium.

---

## Deliverables

### 1. `core/hosts.py` — the host population

N hosts per (src, dst, SLA) scope. Each host independently samples a path set from the
published advisory, generates traffic, and reports what it experienced. Configurable:
population size, SLA mix, arrival/departure, and a **defector fraction** that ignores the
advisory and plays greedy (this is the PAS v3 adversary taxonomy; wire the hook now, the
classes come in M6).

Sampling is independent by design. The realised split concentrates on the intended split
at `O(1/√N)` with no coordination, and that property is what the whole stochastic-advisory
argument rests on. Test it directly.

### 2. Loop closure

`advisory → host sampling → per-link offered load → link state → observations → advisory`.

Advisory application is **delayed by the model's decision latency**. A decision taken 800
simulated ms after the state it was computed from is applied against the state that exists
800 ms later. Invariant 3, made concrete.

### 3. Multi-scope

Many (src, dst) pairs active simultaneously, sharing links. Cross-scope coupling through
shared bottlenecks is where the interesting behaviour lives and where a single-scope
harness would mislead.

### 4. `instrument/detectors.py` (first cut) — oscillation

Oscillation index: spectral peak dominance restricted to the fast band, excluding slow
environmental drift. The existing implementation in `conformance` is correct in principle;
port it, and note in the code why the fast-band restriction exists (environment tracking is
not oscillation, and an earlier version conflated them).

---

## Acceptance criteria

- [ ] Greedy reference model oscillates at `realistic` scale, oscillation index > 0.5
- [ ] Stochastic reference does not, index < 0.15, same scenario and seed
- [ ] Realised split matches intended within the `1/√N` envelope at N = 100, 1k, 10k
- [ ] Decision latency demonstrably shifts application time; a slow model is measurably worse
- [ ] Multi-scope run with ≥ 100 concurrent scopes over `realistic` completes in budget
- [ ] Defector fraction hook exists and a 20% always-greedy population changes the outcome
- [ ] Whole loop deterministic from seed

## Must not break

Determinism. Invariant 3.

## Notes

**This milestone contains the project's headline result.** The figure is link utilisation
over time, ranked-advice versus sampled-advice, at realistic scale. If it does not
reproduce here, that is the most important negative finding the project can produce and it
must be reported, not tuned away.

### The headline, at the smoke tier, 240 rounds, seed 7

Both models on one scenario, one seed, one set of scopes; nothing differs but the model.
`docs/evidence/m3-scope-sweep.log`, reproducible with `scionarena demo`:

| scopes | cadence | amplitude, greedy | amplitude, stochastic | ratio | cost ratio | dominance, greedy | dominance, stochastic |
|---|---|---|---|---|---|---|---|
| 4 | 30 s | 3.33 | 0.32 | 10.5x | 2.06x | 0.330 | 0.076 |
| 8 | 30 s | 3.25 | 0.54 | 6.0x | 2.89x | 0.507 | 0.148 |
| 16 | 71 s | 3.00 | 0.30 | 10.2x | 1.53x | 0.712 | 0.157 |
| 24 | 121 s | 4.46 | 0.24 | 18.7x | 1.32x | 0.848 | 0.279 |

**The oscillation is real and large at every scale.** The greedy model throws its whole
population from one path to another and back; the amplitude ratio never drops below six.

**The proposal's index is not scale-stable, which is why it is no longer the criterion.**
Peak dominance climbs from 0.33 to 0.85 across a 6x change in the number of scopes,
straight through the 0.5 threshold, so that threshold means different things at different
sizes. Series length does the same: at 4 scopes, 100 rounds gives 0.375 against 0.249 and
240 rounds gives 0.330 against 0.076. The criterion is therefore restated as a ratio
between two models on one scenario, with amplitude as the headline; both numbers stay on
the report card.

**One claim was withdrawn.** ADR 0010 first reported that dominance ranked the two models
*backwards*. That measurement was taken before the cadence bug below was found, on a
series that was not uniformly sampled. It does not reproduce, and the ADR says so.

### Three bugs worth carrying forward

1. **The decision cadence did not fit the round, and nothing looked wrong.** Probes are
   charged per scope, so a round's cost grows with the number of scopes: at 40 scopes all
   240 rounds overran a 30 s cadence and the world advanced by whatever the turns happened
   to cost. The series was still the right length and the numbers were still plausible.
   Every detector here assumes uniform sampling and none of them can tell when that is
   untrue. `run_loop` now calibrates the cadence from a few unsampled rounds; the cadence
   it kept is on the report card.
2. **Ranking tracked interfaces by raw crossings picks the ones that cannot move.** An
   interface every path of a scope uses -- the access link out of the source -- carries
   the whole scope whatever the advice says, so a figure drawn on it shows every model as
   calm. Interfaces are ranked by contestedness, `p(1-p)`, and there is a test.
3. **A reference model that was quadratic in the size of the network.**
   `ReferenceStochastic._path_load` asked, for every path and every link on it, which of
   the paths the model had ever seen crossed that link -- inside the MSA loop, so
   `msa_iters` times per advisory, against a path table that accumulates across scopes
   and rounds. At the smoke tier this is invisible. At the realistic tier it was over two
   minutes per decision round against 1.7 s for the greedy model, which is why the
   ">= 100 concurrent scopes" criterion could not be demonstrated at all until it was
   found. The totals need one pass over the demand vector: **150 s per round to 7.8 s**.
   `AnalyticalWorld.path_metrics` had the same shape and is fixed with it.

   The guard is not a timing test. Measured, the quadratic version answered the guard's
   own case in 1.5 s, under any threshold that would not flake; what catches it is
   `test_predict_does_not_rescan_every_path_the_model_has_seen`, which hands the model a
   path table that refuses to be enumerated, and
   `test_the_cost_of_an_advisory_does_not_grow_with_the_rest_of_the_network`, which counts
   lookups instead of seconds.

### Dev tier, 40 concurrent scopes, 240 rounds, seed 7

`docs/evidence/m3-dev-slow/`, the same scenario with a third run of the greedy model given
eight extra seconds of decision latency:

| model | cadence | amplitude | split amplitude | dominance | mean cost | overruns |
|---|---|---|---|---|---|---|
| greedy | 126 s | 5.11 | 0.476 | 0.559 | 2213 ms | 176/240 |
| stochastic | 136 s | 0.29 | 0.154 | 0.840 | 1233 ms | 151/240 |
| greedy, +8 s latency | 124 s | 4.60 | 0.477 | 0.477 | 2217 ms | 188/240 |

The amplitude ratio is 17.7x, the strongest separation measured anywhere. The other two
ratios fall below their thresholds -- split amplitude 3.1x against 4x, cost 1.80x against
2x -- because at this level of contention the stochastic model is congested too: its own
cost roughly triples between 8 and 40 scopes. Contention hurting both models is the
expected physics, not a measurement failure, but the thresholds were set at the smoke tier
and do not transfer, which is the same lesson as the dominance column.

**These runs did not keep their grid**, and the frequency-domain columns above should not
be quoted. See below.

### Realistic tier, 100 concurrent scopes, 80 rounds, seed 7

2,000 ASes, 10,000 links, 20,000 hosts. `docs/evidence/m3-realistic/`, 888 s for both
models:

| model | cadence | amplitude | split amplitude | dominance | mean cost | overruns |
|---|---|---|---|---|---|---|
| greedy | 257 s | 0.144 | 0.491 | 0.349 | 2059 ms | 71/80 |
| stochastic | 267 s | 0.012 | 0.235 | 0.886 | 1325 ms | 62/80 |

**The separation survives as a ratio and collapses as a quantity.** Link amplitude still
ranks the models 12.1x apart, the fourth tier in a row to do so. But the absolute swing is
0.144 against 3.25 at the smoke tier: 100 scopes spread over 10,000 links barely move any
one of them, so the interface the figure is drawn on is nowhere near contested. The
oscillation is real and it is no longer *concentrated*. Which of those two facts matters
depends on a question this milestone does not answer -- whether a deployed recommender
serves a small number of hot scopes or a diffuse many -- and it is the first thing M6's
scenario design has to decide.

**Three of the five demo criteria fail here, and none of the failures are new.** Split
amplitude (2.09x against 4x) and cost (1.55x against 2x) fall for the reason the dev tier
already showed: contention hurts both models, and thresholds calibrated at the smoke tier
do not transfer. Peak dominance is 0.349, below the 0.5 the proposal asked for, having
been 0.848 at 24 smoke-tier scopes -- the clearest demonstration yet that the number moves
with the shape of the experiment. And 71 of 80 rounds missed the grid, so the two
frequency-domain columns above should not be quoted at all; `grid_uniform` is `false` on
that report card.

**What bounds this run is memory, not time.** Measured per decision round at this tier and
scope count: 1.9 s and 21 MiB for the greedy model, 8.2 s and **257 MiB** for the
stochastic one. The clock is comfortable -- 80 rounds is 15 minutes -- but the retained
history is not, and it is retained by design: invariant 1 says the harness never
summarises, so every observation stays addressable for the whole episode. A 120-round run
needs roughly 34 GiB and did not fit in this machine's 31.6 GiB, which is why the
committed run is 80. The stochastic model costs 12x the greedy one per round because it
lights up 12x the paths, so **the price of never summarising is paid mostly by the model
that explores** -- a property worth knowing before M7 puts an RL agent in this loop.

### Known limitation: the sample grid at scale

Series are sampled once per decision round, so a uniform sample grid requires every round
to fit the cadence. Calibration (worst of three unsampled rounds, plus 30%) fixes the
smoke tier and does not fix the dev tier: 176 of 240 rounds overran at 40 scopes even
after the cadence had widened to 126 s.

The cause is that a round gets more expensive as the episode runs. Telemetry is charged
per record, and both models -- the stochastic one far more -- light up more paths as they
go, so the cost of draining a round's observations grows monotonically and a cadence fixed
from the first few rounds is an underestimate by the end. Widening it again mid-run would
destroy the property it exists to protect.

The fix is to sample on the world's own clock rather than once per decision round,
decoupling the sample grid from what the model spends. It changes what a series *is* and
every detector test with it, so it belongs at the start of M4 rather than bolted onto the
end of M3. Until then `grid_uniform` is on every report card and is `false` for exactly
the runs whose spectra are meaningless.
